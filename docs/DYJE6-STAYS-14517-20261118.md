The narrower render gate had required WordPress's `is_main_query()` and
`in_the_loop()` flags. Newspaper's custom post content presentation can render
outside the standard main Loop; this is a likely explanation for the mismatch
between the available stylesheet and missing transformed article. The
successor invokes the same strict post-ID, queried canonical, status,
timestamp and *full source SHA* checks but does not require loop flags for
`the_content`. This gate remains a fail-closed, source-locked one-post render
correction, not a content write or generic site-wide filter. The added
verbatim WP-source fixture tests both normal-loop and off-main-loop render
and source-drift rejection in CI. **Live status remains unverified pending a
new guarded deploy and fresh public proof.**

Second guarded deployment of PR #259 succeeded (#44318018201), but the
independent public workflow #44318377262 again returned zero markers. Its
diagnostics showed `css_deployed=true`, `stale_price_visible=true`, proving
the plugin is loaded but the transformation fails closed. Inspection of the
authenticated WordPress fields identified the *other* relevant difference:
`content.raw` is compact HTML with no internal-link-manager bivak `<a>`
element; `content.rendered` inserts newlines, additional `<p>` tags and the
`data-internallinksmanager...` anchor. The original source-locked four exact
spans match `content.rendered` but not `content.raw`. The `the_content`
filter must therefore run **after** WordPress formatting and internal-link
enrichment, not at priority 75. This successor moves only Dyje 6's filter to
`PHP_INT_MAX` and adds a second, fully rendered WordPress fixture whose
`transform()` must succeed in CI before another guarded deploy. This avoids
further blind relaxation of canonical, source or link-conservation guards.
